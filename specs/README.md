# specs/

Acá vive un directorio por feature, creado por Spec Kit:

```
specs/
└── 001-onboarding/
    ├── spec.md      ← QUÉ y POR QUÉ (criterios de aceptación)
    ├── plan.md      ← CÓMO (frameworks, arquitectura, riesgos)
    └── tasks.md     ← desglose en tareas chicas y verificables
```

Regla de oro: **el spec es la fuente de verdad, no el chat**. Si la
implementación revela que el spec estaba mal, se corrige el spec primero.
Commiteá esta carpeta siempre: es la memoria del proyecto.
